# 제출 — 무스타파 착륙장 플레이 가능한 스테이지 시제품 (2026-10-16)

- **기준 배치**: A3b(임시 작업 기준, 영화 고증 확정 아님). A3·H1은 비교용으로 보존했다.
- **범위**: 치수 탐색 없이 현재 후보값으로 제작했다. 실내와 다른 결투 구간은 넣지 않았다. 실내 파일은 그대로 보존했다.

## 1. 실행·조작 가능한 시제품
- **게임 저장소 브랜치** `stage/mustafar-landing`(로컬 커밋 243f921):
  - 이 세션에는 Isometric-RPG에 푸시할 권한이 없다(권한 요청이 거부됨). 그래서 패치와 번들로 전달한다.
    - `game_patch/0001-…patch`: `git am`으로 적용
    - `game_patch/stage-mustafar-landing.bundle`: `git fetch <bundle> stage/mustafar-landing`
  - 실행: `npm run dev` → `http://localhost:5173/#stage-landing` → 「스테이지 시작」.
- **바로 해 볼 수 있는 빌드**: `landing_prototype.zip`(채팅 첨부). 압축을 풀고 `python3 -m http.server 8080` → `http://localhost:8080/#stage-landing`.
- **조작**: WASD 또는 좌클릭 이동, 휠 확대·축소, F5 오리지널/리마스터 전환.
- **목표**: 시설 출입구(A자 문 앞)에 닿으면 스테이지가 끝난다.

## 2. 실제 게임에서 확인한 것 (`renders/play/result.json`, Playwright 헤드리스 Chromium)

| 확인 | 결과 |
|---|---|
| 로딩·시작 | 개발 서버와 정적 빌드 모두 오류 없음 |
| WASD 이동 | 됨. 화면 기준 방향 그대로 |
| 클릭 이동(게임 길찾기) | 됨. 상자 옆 → 상자 뒤 → 전투 지점 → 출입구 |
| 상자 충돌 | 상자 안을 클릭해도 밖에 머묾 |
| 가림 | 상자 뒤로 가면 상자 조각이 반투명이 되고 인물이 보임(`04_behind_box.png`) |
| 가장자리 | 판 밖(용암)을 클릭하면 가장자리에서 멈춤, 떨어지지 않음 |
| 전투 연동 이벤트 | `stage:combatArea` 들어감·나감, `stage:combatTrigger` 1회 발생 |
| 종료 | 출입구 문턱 앞 도착 → 페이드 → `stage:exit` 이벤트 |

- **최종 아이소메트릭 화면**(게임 출력 카메라):
  - `renders/final_iso_review.png`: 전체, 1920 px로 줄인 것
  - `renders/final_iso_detail_hd.png`: 상자·출입구 부분, 2배 밀도 원본
- **게임 안 화면**: `renders/play/*.png`.
- **플레이 영상**: `renders/play/landing_play_2x.mp4`(46초, 2배속).
- **충돌 확인**: `renders/collision_overlay_review.png`(초록 = 통행, 빨강 = 막힘, 파랑 = 출구, 노랑 = 전투 영역).

## 3. 전투 제작 세션 연동 정보
`GAME_INTEGRATION.md` §3·§4에 정리했고, 같은 내용이 게임 브랜치의 `docs/STAGE_MUSTAFAR_LANDING.md`에 있다.
- 시작 위치, 전투 영역, 아나킨·상대 시작점, 전투 시작 지점, 출구, 이벤트 6종, `lockExit`·`completeCombat` 호출.
- 맵 작업이 바꾼 공유 파일은 3개(26줄)이고, 전투 쪽 파일은 건드리지 않았다.

## 4. "STYLE U"
저장소, 문서, 첨부 자료 어디에서도 정의를 찾지 못했다. 그래서 게임의 기존 아트 방식에 맞췄다.
- 미리 렌더한 그림.
- 오리지널: 폴아웃풍 색 보정 + 포스터라이즈·베이어 디더.
- 리마스터: 2배 밀도 전체 색.
- STYLE U가 다른 기준이면 알려 주면 맞춘다.

## 5. 완성까지 남은 작업
**영화 동선·배치 (기록만 함, 구조물은 바꾸지 않음)**
1. A3b 문턱 안으로 몸이 들어가지 않는다. 원인은 셋이다.
   - 끝 단이 문 절반 앞을 막는다.
   - 문틀 겹층이 판 위로 돌출해 있다.
   - 문틀 면 너머에 바닥이 없다.
   - 지금은 출구를 문틀 앞에 두었다. 문 안 바닥이나 상자 폭은 영화 근거가 생길 때 정한다.
2. 클릭 이동은 좁은 문턱 앞(0.72 m)까지 길을 못 찾을 때가 있다. 타일 A*의 한계라서 근처 클릭이나 키 이동으로 닿는다. 0.5 m 격자 길찾기로 바꾸는 것을 고려한다.

**시각 완성도**
3. 시설 벽 재질이 나뭇결처럼 보인다(세로 얼룩 잡음). 패널 이음선·리벳·그을음으로 바꿔야 한다.
4. 시설 정면 세부(A자 패널, 처마 아래 장비)가 단순한 상자 형태다.
5. 용암이 정지 그림이다. 흐르는 발광층, 연기·불티 효과(게임 쪽 효과 계층)가 필요하다.
6. 다음 요소는 넣지 않았다(형태 미확인).
   - 판 밑 지지
   - 뒤 절벽
   - 파드메의 우주선(영화에서는 판 위에 착륙)
   - 게임에 있는 `skiff` 소품으로 넣을지 결정이 필요하다.
7. 출입구 돌출부 옆면은 형태 미확인 볼륨이다.
8. 리마스터 배경이 4960×3314 한 장이다. 휴대폰 메모리를 생각하면 타일로 나눌 필요가 있다.
9. 게임 라이트맵(앰비언트·점광원)은 기본값만 넣었다. 처마 조명 원뿔과 용암 반사의 움직임은 없다.

**게임 흐름**
10. 종료 뒤 결과 화면이나 다음 장면으로 넘어가지 않고 페이드와 카드만 나온다.
11. 스테이지 음악 연결(게임에 `mustafar.webm` 있음), 시작 연출, 스테이지 선택 메뉴 진입이 없다.
12. 오프라인 캐시(service worker)에 스테이지 파일이 들어가지 않는다.
13. 휴대폰 성능·터치 조작을 확인하지 않았다.
14. 전투 연결(별도 세션)이 남아 있다. 전투 영역과 시작점은 게임 판단값이다.

**저장소**
15. 게임 저장소 푸시 권한: 허용하면 브랜치로 바로 올린다. 아니면 위 패치·번들을 직접 적용해야 한다.
